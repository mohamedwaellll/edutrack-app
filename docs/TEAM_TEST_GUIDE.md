# دليل اختبار EduTrack للتيم

## تشغيل نسخة الاختبار

1. نزّل نسخة [فرع `feature/team-test`](https://github.com/mohamedwaellll/edutrack-app/tree/feature/team-test) أو فكّ الـZIP اللي اتبعت لك. افتح Terminal في المجلد اللي فيه `package.json`.
2. تأكد إن `node --version` بيعرض `v26.8.1`، الإصدار المحدد في `.nvmrc`. شغّل الأوامر دي على Windows:

   ```powershell
   npm.cmd ci
   npm.cmd run demo
   ```

   على macOS وLinux استخدم `npm` بدل `npm.cmd`.
3. استنى رسالة `EDUTRACK LOCAL DEMO READY` وافتح [الديمو المحلي](http://127.0.0.1:4179). سيب الطرفية مفتوحة أثناء الاختبار واضغط `Ctrl+C` لما تخلص.

الديمو بيشتغل ببيانات تجريبية على جهازك. تحديث الصفحة بيحتفظ بالبيانات طول ما الديمو شغّال. إيقاف الديمو وتشغيله تاني بيرجّع البيانات التجريبية من البداية. لو المتصفح احتفظ بجلسة قديمة، اعمل **Sign Out** وادخل تاني.

| الدور | البريد التجريبي |
| --- | --- |
| الأدمن | `admin.demo@edutrack.local` |
| المدرّس | `teacher.demo@edutrack.local` |
| الطالب | `student.demo@edutrack.local` |
| وليّ الأمر | `parent.demo@edutrack.local` |

كلمة المرور للأربعة `demo-password`. استخدم مجموعة **Physics Group F1** والطالب **Youssef Tariq (`ET-F-101`)**. بطاقة المسح موجودة في [`scripts/demo/et-f-101-card.png`](../scripts/demo/et-f-101-card.png). كل دور بيفتح بوابته بعد الدخول.

## سيناريوهات الأدمن

| الميزة | اعمل إيه | المتوقع |
| --- | --- | --- |
| نظرة عامة | افتح **Overview** ثم قارن عدّادات الطلاب والمجموعات مع الشاشات التفصيلية | العدّادات تعكس بيانات الديمو، والقائمة تنقلك لباقي الشاشات |
| الطلاب والمدرسون والمجموعات | أضف سجلات تجريبية، وعدّل بيانات مجموعة وجدولها وسعتها، واسند مدرسًا لها ثم غيّر الإسناد | التغييرات تفضل بعد Refresh. البريد المكرر للمدرّس يظهر كخطأ. استخدم السجلات الإضافية عشان تسيب مجموعة يوسف متاحة لباقي الرحلة |
| البحث وحالة القيد | ابحث في **Students** بكود الطالب. أوقف طالبًا ثم أعد تنشيطه | البحث يحدد السجل الصحيح، والطالب الموقوف ما يقدرش يسجّل حضور جديد بالـQR |
| ربط الحسابات | افتح **Account Linking** وراجع ربط المدرّس والطالب والابن. في آخر الجولة جرّب فك ربط واحد وتأكيده ثم أعد الربط | البوابة المرتبطة تعرض السجل الصحيح. بعد فك الربط وتحديث البوابة، يظهر أن الحساب غير مربوط أو يختفي الابن. بيانات السجل الأصلي تفضل محفوظة |
| البطاقات وQR | افتح **Student ID Cards** لمعاينة أو طباعة البطاقة. من **Attendance → QR Attendance Scanner** اختر مجموعة يوسف وارفع صورة البطاقة من **Upload Image** مرتين بفاصل 3 ثوانٍ على الأقل | أول مسح يسجّل `Present` ووقت الوصول. التاني يعرض `Already Recorded` مع سجل واحد والوقت نفسه |
| كاميرا الكمبيوتر | لو عندك Webcam، افتح **Start Camera** واسمح بالإذن ووجّه البطاقة للعدسة، ثم اضغط **Stop Camera** | المعاينة تشتغل وتقف عند الطلب. لو الكاميرا غايبة أو الإذن مرفوض، سجّل `BLOCKED` لمسار الكاميرا واستخدم رفع الصورة |
| تصحيح الحضور والتصدير | من **Manual Roster** اختر نفس المجموعة والتاريخ. غيّر `Present` إلى `Absent`، اعمل Refresh واضغط **Download CSV** | الحالة تبقى `Absent`، وقت الوصول يبقى فاضي، والـCSV يطابق المجموعة والتاريخ المعروضين. أعد الحالة إلى `Present` لو عايز تعرض حضور يوسف في البوابتين |

## رحلة المدرّس والطالب ووليّ الأمر

| الميزة | اعمل إيه | المتوقع |
| --- | --- | --- |
| درجات وملاحظات المدرّس | ادخل **Teacher Portal**، اختر المجموعة ويوسف بالكود `ET-F-101`، وأضف درجة `18/20` وملاحظتين مختلفتين: `Internal Only` و`Visible to Parent` | الدرجة والملاحظتان يظهروا للمدرّس. محاولة إدخال `21/20` تظهر خطأ |
| حضور ودرجات الطالب | ادخل **Student Portal** واعمل Refresh | الطالب يشوف حضوره ودرجته فقط. ملاحظتا المدرّس تفضلوا خارج بوابة الطالب |
| نشر وتعديل واجب | من **Assignments** في بوابة المدرّس انشر واجب بعنوان واضح وموعد مستقبلي بتوقيت القاهرة. ارفق PDF اختياري حتى 5 MB. غيّر التعليمات قبل أول تسليم | الطالب يشوف آخر تعليمات والموعد والمرفق نفسه بعد Refresh. تعديل الواجب بعد وجود أول تسليم يُرفض |
| تسليم نص أو PDF | افتح **Group Assignments** كطالب. افتح ملف الواجب، وسلّم نصًا أو PDF حتى 5 MB أو الاتنين. حدّث الإجابة أو الملف قبل الموعد | تسليم واحد بآخر نسخة ووقت آخر تسليم. بعد الموعد يفضل اللي اتسلّم محفوظ والتعديل يتقفل |
| متابعة وتصحيح الواجب | كمدرّس افتح **View Submissions**. راجع عدّادات وفلاتر التسليمات. افتح الواجب المحمّل مسبقًا **واجب الحركة (تجريبي)** للتصحيح فورًا. احفظ `18/20`، ثم عدّل إلى `19/20` | الدرجة تتحدّث في نفس السجل، وتظهر للطالب تحت الواجب وفي سجل الدرجات. درجة `0/20` تظهر كمصحّحة كمان. الواجب المفتوح يسمح بالتصحيح بعد انتهاء موعده |
| متابعة وليّ الأمر | ادخل **Parent Portal** واختر يوسف. راجع الحضور والدرجات والملاحظات وقسم **Child Assignments** | الملاحظة المسموح بعرضها تظهر. الملاحظة الداخلية ونص إجابة الواجب وملفها خارج صلاحيات وليّ الأمر. حالة الواجب والموعد والدرجة بتظهر |
| تقويم المواعيد والتنبيه | انشر واجبًا مستحقًا خلال الـ48 ساعة الجاية. افتح تقويم الطالب ووليّ الأمر واختار يوم التسليم، وراجع تنبيه المواعيد في بوابة الطالب قبل تسليم الواجب | يوم التسليم يبيّن الواجب وميعاده بتوقيت القاهرة. تنبيه الطالب يعرض الواجب غير المسلّم القريب من موعده |
| محادثة المجموعة | كمدرّس ابعت رسالة من **Group Discussion**. ادخل كطالب واضغط **Refresh** وردّ عليها. ارجع للمدرّس واعمل Refresh | الحسابان يشوفوا الرسالتين من نفس المجموعة. الديمو يعرض وضع التحديث اليدوي. اختبار WebSocket له أمر مستقل تحت |
| عربي وإنجليزي والوضع الداكن | بدّل اللغة والمظهر من شاشة الدخول ومن بوابة، ثم اعمل Refresh. كرّر على عرض موبايل `360px` | الإعدادات تفضل محفوظة واتجاه العربي RTL. زر الحفظ والخروج متاحين، و`18 / 20` تفضل بالترتيب الصحيح |
| الجلسات والصلاحيات | اخرج من حساب وادخل بدور مختلف. من أدوات مطوّر المتصفح فعّل وضع **Offline** قبل طلب قراءة داخل البوابة، ثم ارجع **Online** واضغط `Retry` | كل حساب يفتح بوابته. عند تعطل القراءة يظهر خطأ وزر إعادة محاولة، وبعد رجوع الاتصال تُعرض البيانات |

## اختبارات آلية واختبارات Docker

شغّل فحوص المشروع من نفس المجلد:

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

لاختبارات البريد والملفات والشات اللحظي وتعارض التصحيح، شغّل Docker أولًا. أوامر Supabase بتجهّز قاعدة اختبار محلية، واختبار البريد يحتاج Chrome متثبّت ومنفذ `3000` فاضي:

```powershell
npx.cmd supabase start
npm.cmd run test:recovery:local
npm.cmd run test:storage:local
npm.cmd run test:chat:realtime
npm.cmd run test:grading:concurrency
npx.cmd supabase stop
```

- **استعادة كلمة المرور:** رسالة حقيقية في Mailpit المحلي، الرابط يفتح صفحة كلمة المرور، القديمة تترفض والجديدة تفتح بوابة المدرّس، والرابط المستخدم يترفض.
- **تخزين PDF:** رفع وتنزيل مرفقات الواجب والتسليم مع رفض الوصول للطلاب أو أولياء الأمور غير المصرّح لهم.
- **Realtime:** وصول أحداث المدرّس والطالب باتصالين فعليين وعزل طالب من مجموعة تانية.
- **تزامن التصحيح:** طلبان على نفس التسليم، طلب واحد يحفظ والتاني يرجع بنتيجة التعارض، مع سجل درجة واحد.
- **مؤجّل:** مسح بطاقة مطبوعة بكاميرا iPhone Safari والبث المباشر داخل EduTrack. اختبار صورة البطاقة متاح في الديمو.

## نتيجة الاختبار

ابعِت اسم الميزة والدور، ونسخة الـZIP أو معرّف الـcommit، والجهاز والمتصفح. اختار `PASS` أو `FAIL` أو `BLOCKED` واكتب خطوات التكرار والنتيجة المتوقعة واللي حصل. لو فيه لقطة شاشة، احذف منها أي بريد أو بيانات حقيقية قبل المشاركة.
